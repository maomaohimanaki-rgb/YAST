## Causa de cada sintoma

| Erro no log | Efeito | Correção (convert.py / molang.py) |
|---|---|---|
| `unhandled request for unknown variable 'variable.X'` | Bedrock devolve 0 para a **expressão inteira**. `AllBody: scale = 1 - v.roaming_a` → 0 → corpo some (Magical Fox; o cajado está fora do AllBody). Acessórios escondidos por `scale: v.x` ficam errados. | `initialize` zera toda variável lida pelo modelo (exceto as protegidas por `??`). |
| `unknown child schema option type. Allowed types: 'array' 'object'` | Keyframe com número solto (`"0.0": 0.0`) ou `post: {post: [...]}` aninhado: o Bedrock **rejeita a animação inteira**. Huowang perdia walk/run/sneak/swim → "anda duro". | Todo keyframe vira `[x, y, z]`; aninhamento é desfeito. |
| `Precomputed cubic interpolation requires keyframes have constant data` | Canal com `catmullrom` + expressão Molang é rejeitado (climb de quase todos, swing da Aventurine). | Canal com keyframe dinâmico usa `linear`. |
| `Brace sections must only contain semicolon-delimited expressions` | `{data3}` (placeholder quebrado no próprio modelo) inválido. | `{expr}` sem `;` vira `(expr)`; validador exige `;` dentro de blocos. |
| `child '默认' not valid here` | Estado de controlador com nome não-ASCII derruba o controlador. Osso com nome vazio idem. | Estados renomeados para ASCII (transições e `initial_state` acompanham); osso vazio é ignorado. |
| `variable.melee_spear_equipped` | Variável que o `player.entity.json` interno do jogo define e a cópia do bedrock-samples não. | Definida no `pre_animation` do override. |

## Cabelo (física)

Os modelos usam um "motor de física" do YSM 1: uma animação de **1 frame** (`animation_length`
0,01–0,0167) cuja `timeline` integra molas em passo fixo de 0,01, num ping-pong entre as chaves
0.0 e 0.0101. No Bedrock os eventos de timeline de um loop menor que o frame disparam de forma
irregular (o FPS do celular varia), então a mola acelera, trava ou explode.

Agora essas timelines viram código no `pre_animation`, executado
`round(delta_time / duração)` vezes por frame (1 a 6). O passo continua sendo o 0,01 do modelo
(estável), e o ritmo segue o tempo real como no conversor 0.4.x, mas sem trocar a constante do passo.
As constantes das molas (`v.L1_F`, `v.L1_K2`...), que ficam numa timeline de 0,5 s, também
rodam no `initialize`, para a física nunca começar dividindo por zero.

Observação: na Hanfu o cabelo comprido (`parallel2`) usa `v.L*_LongHair_k1/k2/k3`, que **o
modelo nunca define** (nem no Java). Essa parte fica parada; a franja (`parallel0`) é a que mexe.
